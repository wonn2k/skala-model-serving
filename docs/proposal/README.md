# 기획서 (섹션별 파일)

발표 기획서 ①~⑥을 섹션마다 파일 하나로 둔다. 파일이 다르면 병합 충돌이 나지 않는다.

| 파일 | 내용 | 만드는 방법 | 주인 |
|---|---|---|---|
| `01_pain_point.md` | ① 이해관계자 가치 (Pain Point) | 사람이 쓴다 (초안 있음) | E |
| `02_solution_and_goals.md` | ② AI 솔루션과 운영 목표 | 사람이 쓴다 (초안 있음) | E |
| `03_operations_design.md` | ③ 운영 설계 | 사람이 쓴다 (초안 있음). 팀 결정이 나면 갱신 | E |
| `04_architecture.md` | ④ 아키텍처 구성도 | **코드가 모두 완성된 뒤** 프롬프트 4로 생성 | E |
| `05_api_spec.md` | ⑤ API 명세 | **코드가 모두 완성된 뒤** 프롬프트 5로 생성 | E |
| `06_snapshots.md` | ⑥ 동작 화면 스냅샷 | **코드가 모두 완성된 뒤** 프롬프트 6으로 생성 | E |

규칙

- **코드 PR은 이 폴더를 건드리지 않는다.** 코드 PR이 고치는 문서는 `docs/code_current.md`의 자기 영역 섹션뿐이다.
- ④⑤⑥은 손으로 고치지 않는다. 고칠 것이 있으면 원자료(`docs/code_current.md`, 코드)를 고치고 프롬프트를 다시 돌린다.
- 수치는 `docs/code_current.md`, `data/README.md`, `docs/PROJECT_PLAN.md`에 있는 값만 쓰고 출처를 괄호로 적는다. 측정하지 않은 값은 "미측정"으로 둔다.
- 프롬프트는 팀 노션 "기획서 작성 단계별 프롬프트" 페이지에 있다.
- 발표 자료·리허설은 개발이 끝난 뒤 별도로 진행한다.
