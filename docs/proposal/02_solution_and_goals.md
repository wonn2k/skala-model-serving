# ② AI 솔루션과 운영 목표

## 핵심 기능

운영 담당자가 전날 보는 화면은 카드 하나다.

> **내일(YYYY-MM-DD) 도착 여객 예측: 39,800명 · 보통**

- 예측값: 다음 날 제주공항 도착 여객 수 (명).
- 혼잡 등급: 예측값이 **40,177명을 넘으면 혼잡**, **34,962명 미만이면 여유**, 그 사이는 보통. 경계는 2023~2025년 실데이터의 사분위 Q3, Q1이다 (`data/README.md`). 상위 25% 날을 혼잡, 하위 25% 날을 여유로 본다는 뜻이다.
- 함께 보이는 것: 최근 20일 도착 여객 추이, 현재 서비스 중인 모델 버전, 재학습 이력.

등급을 붙이는 이유는 운영 담당자가 숫자가 아니라 "평소보다 많이 준비할 날인가"로 판단하기 때문이다.

## 서빙되는 모델의 역할

모델은 **최근 20일의 (도착 여객, 출발 여객)을 넣으면 다음 날 도착 여객 하나를 돌려주는 함수**다 (`data/features.py`, `SEQ_LEN = 20`). 출발 여객을 같이 넣는 이유는 도착과 출발이 같은 수요를 반영하기 때문이다 (출발 여객 평균 37,297명, 도착 37,218명, `data/README.md`).

모델 내부(LSTM 3층)는 이 기획서에서 다루지 않는다. 우리가 만드는 것은 모델이 아니라, 모델을 **매일 안정적으로 쓰고, 안전하게 바꾸고, 나빠지면 알아채는 체계**다.

## 무엇이 어떤 불편을 해결하나

①에서 정의한 세 상황을 세 층이 나눠 맡는다.

| ①의 불편 | 해결 기능 | 담당 기술 | 코드 |
|---|---|---|---|
| 모델이 노트북 안에만 있다 | 예측을 API로 제공. 대시보드가 매일 자동으로 호출 | 서빙 (FastAPI, Pydantic 입력 검증, 헬스체크, Lazy/Eager 로딩) | `serving_app/main.py`, `routers/predict.py`, `schemas.py`, `model_loader.py` |
| 새 모델이 더 나쁠 수 있다 | 학습 기록 → 성능 게이트 → 통과한 버전만 Production 승격 → 컨테이너 배포 | MLOps (MLflow Tracking·Registry, Docker) | `serving_app/train_and_register.py`, `Dockerfile` |
| 모델 품질이 조용히 떨어진다 | 예측·실제 쌍을 쌓아 오차를 감시 → 임계값 초과 시 알림 → 최근 데이터로 재학습 → 게이트 재검증 → 재배포 | AIOps (RMSE 모니터링, aiops.log, fine-tuning) | `serving_app/monitoring/`, `routers/predict.py`의 `batch_test` |
| 응답 지연·장애 | 헬스체크, Lazy/Eager 로딩 선택, 단일 컨테이너 재현 | 서빙 + MLOps | `routers/health.py`, `Dockerfile` |

데이터 공급은 대시보드 CSV 업로드다 (`POST /data/upload`). 한국공항공사 일별 여객 통계를 올리면 학습과 예측이 항상 최신 파일을 쓴다.

## 운영 요구사항

| 항목 | 목표 | 근거 | 측정값 |
|---|---|---|---|
| 예측 품질 | RMSE ≤ 2,700명 (배포 게이트) | 일평균의 약 7%, 전일값 복사(3,600명)보다 25% 좋아야 통과 (`docs/PROJECT_PLAN.md` 2번, `data/README.md`) | Day1 baseline 2,571명, Day2 MLflow 학습 2,267명 (`docs/code_current.md` 2번, PC 1대) |
| 응답 시간 | `/predict` 1초 이내 | 전날 저녁 회의 중 즉시 확인 (`docs/PROJECT_PLAN.md` 3번 ②) | 미측정 |
| 서버 기동 | Lazy 로딩으로 기동 즉시 응답 가능. 컨테이너는 Eager로 기동 시점에 모델 문제를 드러냄 | 수업 가이드 부록 2 | 시작 시간·첫 요청 시간 미측정 |
| 가용성 | 단일 컨테이너로 어느 PC에서나 같은 결과 | `serving_app/Dockerfile` | 미확인 |
| 드리프트 대응 | 오차가 임계값을 넘으면 알림과 재학습이 자동으로 이어짐 | ③ 운영 설계 | 정상·드리프트 배치 RMSE 미측정 (본 레포 기준) |

## 측정 필요 목록

- `/predict` 응답 시간 (첫 요청, 두 번째 요청)
- Lazy / Eager 서버 시작 시간
- 컨테이너에서의 동작 확인
- 정상 배치와 드리프트 배치의 RMSE (팀 PC에서, 이식된 코드로)
