# 조별 미니 프로젝트 기획 — 공항 도착 여객 예측 & AIOps 운영 대시보드

> 상태: **초안 (Sprint 0)**. 팀 회의에서 확정한 내용은 ✅, 확인이 필요한 항목은 ❓로 표시했습니다.
> 발표 기획서는 수업 가이드 8번의 ①~⑥ 순서를 그대로 따릅니다 (①~③ = 평가 2-1, ④~⑥ = 평가 2-2).

## 0. 한 줄 요약

공항 운영 담당자가 **내일 도착 여객 규모와 혼잡 등급**을 전날 미리 확인하고 인력·셔틀·카운터를
조정할 수 있도록, LSTM 예측 모델을 FastAPI로 서빙하고 MLflow 게이트 → 드리프트 감지 → 자동
fine-tuning → 재배포가 한 줄로 이어지는 AIOps 파이프라인을 운영한다.

## 3. 발표 기획서 목차 (①~⑥) — 채울 내용 가이드

### ① 이해관계자 가치 (Pain Point) — 담당: 기획
- 운영자는 내일 도착 규모를 경험·감으로 추정 → 과잉 배치(비용) 또는 과소 배치(대기열·민원).
- 모델이 노트북 안에만 있으면: 매일 아침 수작업 예측, 담당자 부재 시 중단.
- 모델 품질이 조용히 떨어지면(드리프트): 잘못된 예측을 믿고 인력을 배치 → 혼잡·민원 직접 발생.
- 응답 지연/장애 시: 전날 저녁 배치 계획 회의에 예측값이 없음.

### ② AI 솔루션과 운영 목표 — 담당: 기획
- 핵심 기능: 내일 도착 여객 예측값 + 혼잡 등급(예: 여유/보통/혼잡 3단계) 카드.
- 운영 요구사항(초안): `/predict` 응답 1초 이내, lazy 로딩으로 서버 기동 즉시, 품질 목표 RMSE ≤ 2,700명.

### ③ 운영 설계 — 담당: 모니터링
- 배포 게이트: 입력 스키마 검증(SEQ_LEN=20, 값 ≥ 0) + RMSE ≤ 2,700명 통과 버전만 Production.
- 모니터링: 최근 21일 (predicted, actual) RMSE, 임계값 2,700명.
- 대응 정책: `[WARN]` 알림 → 최근 21일 fine-tuning → 게이트 재검증 → 통과 시 재배포 / 실패 시 기존 버전 유지.
- 확장 논의 거리(가산점): 재학습 검증셋 확보 방법, 서빙 캐시 갱신(부록 1의 6번), 롤백.

### ④ 아키텍처 구성도 — 담당: 배포
- 업로드 → `data/uploads/` → 학습(MLflow sqlite, Registry) → FastAPI 서빙(단일 컨테이너) →
  예측 기록(`recent_predictions`) → 드리프트 감지 → aiops.log 알림 → fine-tuning → Production 재배포.
- 팀 서비스명으로 라벨 치환해 화살표 다이어그램으로 작성.

### ⑤ API 명세 — 담당: 서빙 API → [`docs/API_SPEC.md`](API_SPEC.md)

### ⑥ 동작 화면 스냅샷 — 전원
- 모델 버전 전환 전/후 `/predict` 응답, 컨테이너 실행 화면,
  드리프트 주입 → `[WARN]` → `[INFO]` → `[OK]` 로그가 대시보드 재학습 로그 패널에 쌓인 화면.

## 7. 리스크 및 메모

- **게이트 2,700: Day1 baseline RMSE 2,571명으로 1차 통과** (전일값 복사 3,600명). 여유가 약 5%라 Day2 seed 고정 학습 결과로 최종 확정. 37,000은 출발 여객 평균(37,297)과 일치해 확정.
- **시뮬레이션 σ(1.2% / 3.6%)는 주가 기준**이라 제주공항 실변동성(8.4%)보다 낮음 → 랜덤워크 드리프트 배치가 임계값을 못 넘을 수 있음. 시연은 실데이터 배치 `data/jeju_drift_batch_41rows.csv`(2025-02-07 폭설 6,088명 포함)를 우선 사용하고, σ는 실측 기준으로 재조정.
- 서빙 중인 모델 캐시(`_model_cache`)는 재배포 후 자동 갱신되지 않음(가이드 부록 1의 6번) — 해결 방법이 좋은 트러블슈팅 기록이 됨.
- 포트: 스켈레톤 README는 8077, 스크립트·Dockerfile은 8000이었음 → 이 레포는 **8000으로 통일**.
- fine-tuning 검증셋이 21일 중 20% ≈ 4~5개뿐 → RMSE가 우연히 낮게 나올 수 있음. 운영 설계에서 언급하면 가산점.
